Shows what the next change-detection run would do with an rfc-index.json you upload, compared with the live snapshot and the live subscriptions. It runs the same comparison and matching as the real run, in the background, reading the database only inside read-only transactions that are always rolled back: no snapshot, notification, or cache entry is written, and nothing is sent. The run itself is recorded below.

To try one fake or edited RFC, upload just its entry rather than a whole index: Reef fetches Red's live index itself and applies the upload to it. The file is a list of entries, each a whole entry as it appears in rfc-index.json, or an object with an index list and optionally a createdOn. An entry replaces the live one with the same number, and is otherwise added: 

[{"number": 99999, "title": "A fake RFC", "status": {"slug": "ps", "name": "proposed standard"}, …}]
